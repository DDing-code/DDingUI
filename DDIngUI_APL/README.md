# DDIngUI_Attack Priority List

**2.2.0 · Retail 12.1.0 · Interface 120100**

개인 SimulationCraft APL을 공개된 게임 상태로 평가하는 독립 애드온 초안입니다.
전 직업 **40개 전문화의 자동 선택**, **34개 공개 기본 APL 원문**, 개인 APL 편집과 평가,
블리자드 Assisted Combat 대체 경로를 연결했습니다.

**전 직업의 SimC APL을 실전에서 완전히 실행하는 버전은 아닙니다.**
내장 원문에는 아직 지원하지 않는 문법과 상태가 있습니다. 이를 삭제해서 실행하지 않으며,
차단 이유를 보여주고 자동 모드에서는 블리자드 추천을 요청합니다.
현재 내장 원문 **34개를 파싱**하지만 **34개 모두 실행 미지원 명령이 남아 있습니다.**
원문 전체 실행과 전 직업 실전 지원은 미완성입니다. 파싱 성공을 추천 성공으로 집계하지 않습니다.
신규 설치는 APL 전용 모드로 시작하므로 내장 팩에서 미지원 규칙을 만나면 대기합니다.
실행 가능한 범위는 공개 입력과 지원 명령으로 작성한 개인 APL입니다.
기존 사용자의 모드는 유지하고, 개인 APL을 저장/적용하면 APL 전용 모드로 전환합니다.
블리자드 추천도 제공되지 않는 전문화·상황에서는 아이콘 없이 대기합니다.
실제 12.1 클라이언트의 전투·taint·성능·DPS 검증은 아직 하지 않았습니다.

### 0.1.2 개인 APL 실행 경로 수정

- 전투 전/호출하지 않는 목록의 미지원 명령이 전체 APL을 거부하던 문제를 수정했습니다.
  구문 오류는 저장을 거부하고, 미지원 기능은 경고로 보존하여 평가가 도달했을 때 차단합니다.
  해당 규칙이 다른 대상을 선택할 수 있으면 현재 대상의 조건/사거리만으로 건너뛰지 않습니다.
- `floor()`, `ceil()`, 절댓값 `@`, 변수 `reset/default/floor/ceil`, 원문의 빈 쉼표를 처리합니다.
  전투 전 변수 초기화와 틱 간 변수 지속은 여전히 미구현입니다.
- 공개 `isEnabled=true`와 `isActive=false`로 쿨다운 준비 여부를 판단합니다.
  숫자 시간 필드가 비공개라는 이유만으로 준비된 주문을 막지 않습니다.
  근거: [12.1 SpellCooldownInfo 선언](https://github.com/Gethe/wow-ui-source/blob/12.1.0/Interface/AddOns/Blizzard_APIDocumentationGenerated/SpellSharedDocumentation.lua).
  GCD와 실제 쿨다운을 비공개 시간 값으로 구분하거나 예측하지 않습니다.
- `SpellHasRange=false`인 주문은 `IsSpellInRange=nil` 때문에 차단하지 않습니다.
  이름 후보가 모두 배우지 않은 주문인 경우와 ID 미연결/중복을 구분합니다.
- 개인 APL 저장 시 APL 전용 모드로 전환합니다. 자동 대체에서도 APL 결과를 별도로 보존하고
  `/ddapl status`에 차단 목록·행·입력과 미연결 토큰을 표시합니다.
- 블리자드 추천 함수를 차단한 Lua 5.1 검사에서 실제 Core → API → Engine → UI 경로로
  개인 APL 순서/자원 조건 변경에 따라 추천 아이콘이 바뀌고, 비공개 입력이면 멈추는 것을 확인했습니다.
  이는 모의 API 검사이며 게임 내 검증을 대신하지 않습니다.

### 0.1.1 표시 수정

사용자가 EllesmereUI와 행동 단축바를 숨겼을 때 추천이 나타났다 사라지는 조건을 확인했습니다.
추천 조회는 이미 GetNextCastSpell(false)를 사용하고 있었으며, 이번 수정은 다음 경로를 보완합니다.

- IsAvailable 검사로 먼저 중단하지 않고 공개된 GetNextCastSpell(false)의 유효한 값을 우선합니다.
- 정상 조회가 잠깐 빈 값일 때만 직전 기본 추천 아이콘을 최대 0.4초 동안 회색으로 표시합니다.
  이때 현재 추천은 여전히 미확인이며 엔진의 상태/우선순위에 이전 값을 넣지 않습니다.
- 대상 변경, 읽기 제한/오류, 가용하지 않은 API, 만료 시에는 이전 표시를 폐기합니다.
- 단축키/행동 슬롯 이벤트는 키 표시만 갱신합니다. 전투 중 SPELLS_CHANGED는 공개 주문 ID 연결만
  다시 확인하며 APL 자체를 버리지 않습니다.
- 실전은 현재 추천 1칸과 후속 예측 미지원 안내를 표시하고, 3칸은 가상 미리보기에서만 표시합니다.
- /ddapl status에 native sample과 보조 버튼 배치/하이라이트 설정을 추가했습니다.

EllesmereUI 설정·기본 행동 단축바·CVar는 변경하지 않습니다. 숨김 상태에서 추천 API가 계속
값을 주지 않는 경우까지 복구했다고 검증한 것은 아닙니다. 수정 적용 후 /reload로 확인합니다.

## 설치와 실행

1. DDIngUI_APL 폴더를 Retail의 Interface/AddOns에 둡니다.
2. **첫 설치는 WoW를 완전히 재시작**한 뒤 애드온 목록에서 활성화합니다.
3. **/ddapl**로 독립 설정 창을 엽니다. 추천 창 우클릭으로도 열 수 있습니다.
4. 일반 페이지에서 표시, 위치 잠금, 크기, 추천 모드, 수동 대상 수를 설정합니다.
   위치는 **편집 모드**(설정 창 제목줄 버튼, 미니맵 우클릭, /ddapl edit)에서 옮깁니다.
5. APL 페이지에서 현재 전문화의 규칙과 별칭을 편집하고 **검증 → 저장 / 적용**합니다.

이 작업 공간에는 Retail AddOns/DDIngUI_APL에서 저장소 소스로 가는 Junction이 설치되어 있습니다.
StyleLib와 LibStub은 내장되어 있어 다른 DDingUI 애드온이 없어도 로드됩니다.

| --- | --- |

| /ddapl preview | 가상 3수 미리보기 전환 |

## 편집 모드

DDingUI 시리즈 공용 편집 모드(StyleLib 1.4)입니다. 설정 창 제목줄의 **편집 모드** 버튼,
미니맵 **우클릭**, **/ddapl edit**로 열고 닫습니다. 전투 중에는 열리지 않으며,
전투가 시작되면 즉시 닫힙니다. 설정 창에서 열었다면 닫을 때 설정 창이 다시 열립니다.

- 추천 창 위의 무버를 드래그합니다. 위치 잠금과 상관없이 이동하며 잠금 설정은 바뀌지 않습니다.
- 리모컨: X/Y 입력, ▲▼◀▶(1px, Shift 10px), 격자 표시와 간격 16/32/64,
  스냅(중앙/격자, 거리 8. 화면 가장자리 스냅은 스냅이 켜져 있으면 항상 적용), 초기화/실행 취소/다시 실행/완료.
- 키보드: 방향키 이동(Shift ×10), Ctrl+Z/Ctrl+Y, Esc로 종료. 드래그 중 Shift는 스냅을 잠시 끕니다.
- X/Y와 좌표 표시는 화면 중앙 기준 화면 단위입니다. 저장은 기존처럼 창 크기 배율 단위
  (DDIngUI_APLDB.x / y)로 환산하므로 크기를 바꿔도 같은 자리에 있습니다.
- 리모컨을 옮긴 위치는 캐릭터별 DDIngUI_APLDB.editRemotePos에 저장합니다.

## 추천 출처

- **APL**: 개인 규칙을 읽을 수 있는 현재 입력으로 평가한 다음 1수.
- **BLIZZARD**: C_AssistedCombat의 기본 추천. 개인 APL·수동 대상 수는 적용되지 않습니다.
- **PREVIEW**: 생성/소모 자원 모델로 실행하는 가상 3수. 실전 전문화 예측이 아닙니다.

자동 대체 모드는 APL → 기본 추천 순서입니다. APL 전용 모드는 자체 APL만 평가하고,
판단할 수 없는 상위 규칙이 있으면 대기합니다. 기본 모드는 블리자드 추천만 표시합니다.
후속 두 칸은 검증된 실전 효과 모델을 만들기 전까지 숨기고 미지원 상태를 안내합니다.
자동 시전이나 클릭 시전 기능은 없습니다.

## 개인 APL 예시

아래는 징벌 성기사의 **입력/평가 확인용 예제**이며 최적 딜사이클이 아닙니다.

~~~text
actions=/spender,if=holy_power>=3
actions+=/generator
~~~

별칭 입력:

~~~text
spender=85256
generator=35395
~~~

현재 캐릭터가 배운 주문인지, 공개된 사용 가능 여부·쿨다운·사거리 조건이 맞는지 확인합니다.
같은 기술의 다른 변형/대체 주문을 쓰는 빌드에서는 실제 주문 ID를 지정해야 합니다.
별칭 없이 actions=/spell_35395처럼 ID 토큰을 쓸 수도 있습니다.

**저장 실패 시 기존 개인 APL을 유지**합니다. 저장 전 상태 한 개는 이전 복원으로 되돌릴 수 있습니다.
기본 팩 버튼은 현재 전문화만 내장 원문으로 전환합니다. 개인 데이터는 캐릭터별
DDIngUI_APLDB.profiles[specID]에 저장하며 다른 DDingUI 저장 변수는 수정하지 않습니다.

## 현재 평가 범위

- actions, actions.NAME, = / +=, if.
- call_action_list / run_action_list의 서로 다른 제어 흐름과 순환 차단.
- variable의 set/add/sub/mul/div/min/max/setif/reset/floor/ceil과 숫자 default.
  setif는 condition/value_else를 사용하고, floor/ceil은 현재 변수 값을 반올림 없이 내림/올림합니다.
- 숫자, 괄호, 부호, !, @, &, |, ^, 비교, +, -, *, %, %%, <?, >?, floor(), ceil().
- SimC의 %는 나눗셈, %%는 나머지, <?는 max, >?는 min입니다.
- 논리식에서 0은 거짓. 미확인은 별도 값이며 false로 치환하지 않습니다.
- 실시간 입력: 수동 active_enemies, in_combat, 공개 자원과 max/deficit/pct,
  공개 cooldown.NAME.remains/ready/up, 공개 player buff.NAME.up/down/stack/remains.
- API가 제한되거나 실패하면 해당 입력은 미확인입니다. nil 오라는 해당 주문의 비밀 제한이
  명시적으로 없고 조회가 성공했을 때만 없음으로 처리합니다.
- 비중첩 버프의 applications=0은 APL stack=1로 정규화합니다.
- 일반 액션 바의 주문 키 바인딩을 표시합니다. 매크로/변신/교체 바 전체 매핑은 미지원입니다.

미지원 옵션/행동은 원문과 행 번호를 보존하고 경고로 보고합니다.
사용하지 않는 목록은 전투 목록의 평가를 막지 않지만, 미지원 규칙에 도달하면 그 지점에서 멈춥니다.
장신구/물약/자동 공격 등의 SimC 명령을 이름이 비슷한 일반 주문으로 오인해 건너뛰지 않습니다.
실제 구문 오류는 개인 팩 저장을 거부합니다.
구문이 지원되어도 미구현 피연산자는 실제 평가에서 미확인입니다.
전투 전 변수 초기화와 틱 간 변수 지속, 특성/장비 효과, target_if, TTD,
적 디버프/DoT, 장신구/물약, 시퀀스, 외부 버프, 조건부 쿨기 보류,
직업별 효과 모델은 아직 구현하지 않았습니다.
심크 내 캐릭터/장비 설정은 가져와 적용하지 않고 게임의 현재 캐릭터를 사용합니다.
apl_variable override는 지원하지 않으므로 명시적으로 차단합니다.

파서는 원문 256 KiB, 표현식 8192 bytes/1024 nodes, 목록 64개, 행동 4096개,
표현식 깊이 64, 목록 호출 깊이 32, 평가 단계 20,000으로 제한합니다.
가져온 내용을 loadstring으로 실행하지 않습니다.
실시간 재평가는 대상/전투/미리보기가 있을 때 최대 10 Hz입니다.

## AuraContainer

일반 페이지에 본인 버프의 주문 ID를 입력하면 추천 창 위에 실제 버프 아이콘·스와이프·중첩을
네이티브 슬롯으로 연결합니다. 빈 값으로 연결을 숨길 수 있습니다.

Blizzard가 보호된 자식 프레임의 표시를 처리합니다. 해당 프레임의 IsShown, 글자, 너비,
중첩 또는 시간 값을 읽어서 APL에 넣지 않습니다. 공개된 buff 조건은 별도의 API 조회 경로입니다.
따라서 **실제 버프 표시 연결과 APL 조건 평가 가능성은 별개**입니다.
생성한 슬롯의 주문 ID를 바꾸면 /reload가 필요합니다.
이 바인딩은 목 환경에서 생성 경로만 확인했으며 실제 게임 반응은 미검증입니다.

## 검증과 남은 관문

2026-09-28에 실제 Lua 5.1로 TOC의 라이브러리/런타임 로드, 수식, 미확인 논리,
우선순위 차단, call/run, 잘못된 가져오기 보존, 전투 설정 제한, 기본 추천 전환,
설정 페이지 생성, 40개 전문화 전환, 34개 원문 파싱/SHA256 일치를 검사했습니다.
0.1.2는 도달하지 않는 미지원 목록과 도달하는 차단 규칙, 대상 선택 보존,
공개 준비 여부/비공개 시간, 사거리 없는 주문, ID 미연결과 배우지 않은 주문 구분,
블리자드 호출 0회에서 개인 APL 조건/순서에 따른 실제 렌더링까지 확인했습니다.

저장소 루트에서 실행:

~~~powershell
python DDIngUI_APL/tools/test_alpha.py
python DDIngUI_APL/tools/test_editmode.py
~~~

개발 검사는 설치된 lupa.lua51과 저장소의 test_dashboard_workspace.py 프레임 더블을 재사용합니다.
목 검사는 게임 API의 비밀 값/taint 정책이나 UI 모양을 검증하지 않습니다.
게임에서 /ddapl preview → 공개 입력 개인 APL → 자동/엄격 전환 → 전문화 전환 →
버프 하나의 표시 → 허수아비/인스턴스 전투를 순서대로 확인해야 합니다.

정식 개발의 다음 관문은 실제 전문화별 접근성 측정과 주문 효과 모델입니다.
내장 원문 전체가 실행 가능해지기 전까지 “전 직업 헤키리 대체 완성”으로 표시하지 않습니다.
