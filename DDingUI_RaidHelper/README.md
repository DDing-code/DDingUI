# DDingUI RaidHelper

전투 중 현재 시점을 따라 움직이는 공격대 피해 예측 타임라인입니다. 미리 집계한 로그 피해 파형 위에 보스 기믹과 상위권 힐러가 많이 사용하는 구간의 쿨기 계획을 표시합니다. 실측 피해량이나 모든 공대에 동일한 확정 타이밍을 뜻하지는 않습니다.

## 현재 구현

- `ENCOUNTER_START`/`ENCOUNTER_END` 기반 자동 시작과 종료 — 설치된 레이드 데이터 모델과 일치할 때만 시작하며 던전·데이터 없는 전투는 무시
- 현재 보스·난이도·플레이어 전문화를 인식해 일치하는 데이터 자동 선택
- 최근 12초와 앞으로 38초를 함께 보여주는 스크롤 타임라인
- 평균 받는 피해 파형, 페이즈 경계, 기믹 아이콘, 힐러 쿨기 아이콘
- 앞으로 12초 안에 사용할 선택 쿨기를 아이콘·주문명·남은 시간 형태의 보스 바 목록으로 최대 3개 표시
- BigWigs 보스 바와 페이즈 이벤트를 이용한 실시간 재동기화
- 하나의 `미리보기` 동작으로 3페이즈 반복 재생·드래그 위치 조정·종료 통합
- 타임라인은 기본 잠금이며 표준 LibDBIcon 미니맵 버튼 좌클릭으로 독립 설정 창, 우클릭으로 미리보기와 위치 조정 전환
- 현재 보스·전문화의 상위 힐러 평균 2차 스탯과 대표 특성 코드를 게임 안에서 확인·복사
- CDM·Toolkit과 같은 StyleLib 독립 설정 창에서 타임라인·쿨기 표시·힐러 프로필·데이터 팩 페이지 제공
- 독립 설정 창에서 설치된 영웅·신화 모델 수와 최근 생성 시각을 확인하고 `데이터 다시 불러오기` 실행
- `LibStub`, `CallbackHandler`, RaidHelper 전용 `DDingUI_StyleLib` fallback 내장 — 공용 StyleLib를 선점하지 않고 단독 실행
- 마커 툴팁은 기본 비활성화이며 RaidHelper 독립 설정 창에서 선택 가능
- 전체 배율과 별도로 타임라인 너비(200~1200px)·높이(170~420px)·배경 불투명도 조절
- 현재 힐러 전문화의 주요 힐업·세미 쿨기·외생기·개인 유틸 표시 선택
- 예정 쿨기 보스 바 목록은 타임라인 설정에서 켜고 끌 수 있으며 전투 중 변경은 종료 후 반영
- 전투 중 바꾼 툴팁 설정은 현재 전투에 적용하지 않고 전투 종료 후 반영

## 데이터 갱신 구조

WoW 애드온은 웹 API를 직접 호출하지 않습니다. 외부 갱신기가 Warcraft Logs 공개 API를 이용해 다음 두 표본을 따로 수집하고, 개인 식별 정보와 원본 보고서 코드를 제외한 집계값만 Lua 데이터 팩으로 생성합니다.

- 보스·난이도별 스피드 상위 공개 처치 로그 10개: 피해 파형, 페이즈, 기믹
- 다음 순위 공개 처치 로그 최대 2개: 생성 표본과 분리된 시각 정합성 검증용 홀드아웃
- 7개 힐러 전문화별 HPS 상위 공개 캐릭터 10명: 쿨기, 특성, 2차 스탯

- 페이즈 및 핵심 기믹 기준으로 정렬한 0.5초 구간별 평균 공격대 피해
- 기믹별 평균 피해량과 평균 피격 인원
- 힐러 쿨기별 평균 사용 시각, 오차 범위, 전체 로그 중 사용 비율
- 전문화별 쿨기 타임라인(`cooldownsBySpec`)
- 신성 사제 후광(120517)을 포함한 세미 쿨기와 주문별 표시 기본값
- 전문화별 평균 치명타·가속·특화·유연성 평점과 평균 아이템 레벨
- 전문화별 대표 특성 빌드 최대 3개와 빌드/개별 특성 사용률
- 표본 수, 생성 시각, 데이터 스키마 버전

특성 가져오기 문자열은 WCL 응답에 완성된 형태로 존재하지 않으므로, 저장한 특성 노드와 현재 게임의 특성 트리 해시를 조합해 게임 안에서 생성합니다. `빌드` 창의 `코드 전체 선택`을 누른 뒤 `Ctrl+C`로 복사할 수 있습니다.

생성된 데이터는 `Data/Generated.lua` 한 파일로 원자적으로 교체됩니다. 갱신기는 홀드아웃 로그의 페이즈 구성, 기믹 매칭률·시각 오차, 피해 피크·전체 곡선 유사도, 힐러 보스 시전 앵커 매칭률을 검사합니다. 기준을 벗어난 모델이 하나라도 있거나 갱신이 중단되면 기존 파일을 그대로 유지합니다. 공개 처치가 10개 이하라 독립 홀드아웃을 남길 수 없는 시즌 초 신화 모델은 실제 수집 표본 자체로 검사하되 `validation.status = "limited"`로 명시합니다.

기믹은 페이즈 안의 시간 군집으로 정렬하고 쿨기는 사용률이 높은 군집을 선택합니다. `phase-cast-anchored-v2`부터 피해 파형·힐러 쿨기·홀드아웃 검증은 동일한 보스 시전 기준 시간 변환을 사용합니다. 서로 다른 처치 시간을 비례 축소하지 않으며, 실제로 매칭된 시전 사이에서만 보정하고 마지막 시전 뒤에는 초 단위 간격을 유지합니다. 기준 페이즈 밖 피해를 마지막 칸에 몰아넣지 않고, 쿨기 후보가 적더라도 원본 로그에서 관찰한 최소 반복 간격을 검사합니다.

BigWigs에서는 현재 전투 모듈의 신호만 받으며 바 만료 시각에서 8초 넘게 떨어진 후보는 동기화하지 않습니다. 거절한 후보를 일시정지/재개 때 다시 동기화하거나, WCL 페이즈 순번을 BigWigs stage ID로 취급하지 않습니다. 미매칭 바는 실제 종료 시계를 유지하므로 다른 기믹으로 시간축을 보정해도 남은 시간이 변하지 않습니다. 전문화 공개 표본이 없는 신화 보스는 피해 정합성 검사를 통과해도 `limited`와 `missingHealerSpecs`로 표시하며 해당 전문화의 쿨기를 만들지 않습니다.

같은 기술에 시전 앵커와 피해 시점의 대체 앵커가 함께 있으면, 8초 범위 안의 시전 앵커를 우선합니다. 시전이 늦어졌다고 피해 시점으로 잘못 맞추지 않으므로 시전 후 피해까지의 간격을 유지합니다. 바의 시작·중지·일시정지·재개는 안전한 이벤트 ID 또는 표시 이름으로 같은 바를 찾습니다. 재개 시 이벤트 ID가 있으면 실제 남은 시간을 조회하고, 타임라인 API 값이 없으면 일시정지 시점에 남았던 시간을 유지합니다. 보호된 남은 시간 값은 사용하지 않습니다.

### Warcraft Logs 갱신기

자격 증명은 소스나 명령행에 넣지 않고 Windows 사용자 환경 변수에서만 읽습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\configure_wcl.ps1
python .\tools\update_wcl.py list
python .\tools\update_wcl.py update --difficulty 5 --limit 10 --validation-limit 2
```

명령어 대신 프로젝트의 `Update_RaidHelper_Data.bat`를 더블클릭하면 영웅 전 보스와 공개 처치가 존재하는 신화 보스를 갱신합니다. 시즌 초라 신화 공개 처치가 없는 보스는 건너뛰고, 나중에 BAT를 다시 실행하면 새로 열린 신화 보스도 자동으로 포함합니다. 첫 실행 이후에는 로컬 캐시를 재사용합니다.

BAT 수집기는 최대 8개 작업을 병렬 처리하며 진행률을 즉시 표시합니다. Warcraft Logs 시간당 한도에 도달하면 서버가 알려 준 초기화 시간만큼 모든 요청을 함께 대기시킨 뒤 같은 표본부터 재시도합니다. 최종 파일은 모든 처리가 성공한 뒤에만 교체합니다.

브랜딩 아이콘은 공용 `Branding/DDingUI_Symbol_Orange.png`의 형태와 알파를 그대로 유지하고 RaidHelper 포인트 컬러 `#D65CFF`로 변환한 512×512 RGBA TGA입니다. 투명 픽셀 RGB를 0으로 정리하고 WoW용 top-left 방향으로 저장해 미니맵 스킨에서 보라색 원판으로 보이지 않게 했습니다. `python .\tools\build_brand_icon.py`로 재생성할 수 있으며 TOC, 독립 설정 창, 전투 타임라인이 `Media\RaidHelper_Icon.tga`를 사용합니다.

- `list`는 현재 확장팩의 최신 라이브 레이드와 보스 ID를 표시합니다.
- `update`는 각 보스의 스피드 순위 상위 공개 처치 로그를 기본 10개 수집합니다.
- `--validation-limit 0-10`은 모델 생성에 사용하지 않을 다음 순위 독립 검증 로그 수이며 기본값은 2입니다.
- 힐러 데이터는 각 전문화의 HPS 순위에서 기본 10명을 별도로 수집하며, 비공개·누락 표본은 다음 순위로 보충합니다. 시즌 초 신화에서 공개 후보가 전혀 없는 전문화는 `limited` 모델에서 생략되며 런타임은 해당 전문화의 쿨기를 빈 목록으로 처리합니다.
- `--difficulty 5 4 3`처럼 Mythic·Heroic·Normal을 한 데이터 팩에 함께 만들 수 있습니다.
- `--encounter 3470`을 추가하면 지정 보스만 갱신합니다.
- `--workers 1`부터 `--workers 8`까지 병렬 수를 조정할 수 있으며 기본값은 4입니다.
- 원본 응답 캐시는 `tools/.cache/wcl`에만 저장되며 Git에는 포함되지 않습니다.
- WCL 난이도(`5/4/3/1`)는 WoW 전투 이벤트 난이도(`16/15/14/17`)로 자동 변환됩니다.

각 로그는 WCL의 실제 페이즈 전환 시각을 기준으로 분리한 뒤, 같은 페이즈의 기믹·쿨기를 시간 군집으로 맞춥니다. 특정 로그에서 한 번 사용하지 않은 쿨기가 있어도 이후 사용 시점이 앞 회차와 섞이지 않습니다.

## 명령어

- `/drh preview` — 미리보기와 위치 조정 시작/종료 (`demo`, `edit`는 호환 별칭)
- `/drh stop` — 현재 타임라인 종료
- `/drh reset` — 위치 초기화
- `/drh lock` — 이동 잠금 전환
- `/drh tooltip` — 마커 툴팁 표시 전환 (전투 중에는 종료 후 적용)
- `/drh profile` — 현재 보스·전문화의 평균 2차 스탯과 대표 특성 코드
- `/drh options` — RaidHelper 독립 설정 창 열기

첫 설치가 게임 실행 중에 이루어졌다면 `/reload`만으로 새 폴더를 찾지 못할 수 있습니다. WoW를 완전히 종료한 뒤 다시 실행하고, 캐릭터 선택 화면의 애드온 목록에서 `DDingUI RaidHelper`가 활성화되어 있는지 확인합니다. StyleLib는 RaidHelper에 내장되어 있으므로 별도 `DDingUI_StyleLib` 애드온은 필수가 아닙니다.
